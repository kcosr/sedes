# Codex 0.154.0 release qualification review

Reviewed 2026-09-16 against release tag `rust-v0.154.0`, commit
`6b9826e3aa83b1a5947db50f4332cb9c65f1b340`. Source review compares that tag
with `rust-v0.153.4`; executable exports compare with the committed official
0.153.0 parser baseline. No unreleased branch changes are part of this review.

## Artifact and schema evidence

[Artifact metadata](0.154.0.json) records the exact release tag object and
commit, official npm URLs, published SHA-512 integrities, and computed SHA-256
hashes. The wrapper and Linux x64, macOS arm64, and macOS x64 tarballs were
downloaded and their complete bytes verified against the registry integrities.
Executable hashes were computed after extraction. Only Linux x64 was executed;
macOS entries are artifact-integrity evidence, not runtime qualification.
The `vendor/<target>/bin/codex` layout also exists in the 0.153.0 baseline and
is not a new 0.154.0 integration requirement.

All four export combinations were generated twice into separate output
directories using the verified Linux executable. Each repeated inventory and

records every added or changed path, baseline hash, and candidate hash:

## Semantic review and adopted surface

The upstream paths below are relative to `codex-rs/app-server-protocol` at the
release tag. Generated JSON aggregate changes repeat the same constituent type
changes; TypeScript index changes export those types.

- `src/protocol/v2/thread_data.rs` adds nullable `originator` and experimental
  `environments` / `daybreakEnabled` fields to thread responses and notifications.
  Existing Sedes `projectCodexThread` explicitly projects its adopted fields;
  these additions are not exposed to the browser. Ordinary `ThreadItem` history
  shapes do not change. `thread/list` adds optional `originators` in `thread.rs`;
  Sedes does not send it. A nonempty originator filter is hosted-backend-only.
  Experimental metadata updates add optional `daybreakEnabled`; Sedes does not
  send or advertise it. No environment-selection or Daybreak feature is added.
- `src/protocol/v2/permissions.rs` changes approval `cwd` from `AbsolutePathBuf`
  to `LegacyAppPathString`; `item.rs` makes the same change for Guardian command
  and patch review paths. Both serialize as strings. The newer type preserves
  the target's native path spelling instead of interpreting it on the client
  host. Sedes' permission decoder consumes a bounded string and does not use
  approval `cwd` as local filesystem authority. Guardian review notifications
  remain outside the adopted notification surface. No new path parser is needed.
- `src/protocol/v2/mcp.rs` adds nullable `toolsError` to MCP status and an
  experimental `openai/userVerification` elicitation variant. MCP status is
  not an adopted Sedes RPC. Existing form/URL elicitation shapes are unchanged.
  The new variant is intentionally unsupported and rejected by the pinned
  request validator; do not translate it into an ordinary form or fabricate
  verification proof. New `userVerification/{status,enroll,delete,verify}` APIs
  are not adopted. In this release, `app-server/src/message_processor.rs`
  returns unavailable for all four and `user_verification_auth.rs` reserves
  activation for a later trusted-host signing integration.
- `src/protocol/v2/account.rs` adds optional `supportsLunaReserve` and
  `excludeResetCreditDetails` rate-limit request capabilities, nullable
  `ordinaryUsageAllowed`, and `normalModelSlug` quota metadata. Sedes does not
  adopt these account/rate-limit routes or infer reserve fallback permission.
  This change does not add automatic model fallback or usage UI.
- `src/protocol/v2/application.rs` and `config.rs` add managed application
  network requirements and browser WebMCP policy. These are configuration
  requirement readout additions outside the adopted RPCs. The runtime still
  enforces its own operator policy; Sedes does not implement new policy controls.
- `ResponseItem` adds `configuration_update` with `ConfigurationReasoning`.
  This affects raw response notifications and raw resume history, neither of
  which Sedes requests. The generated ordinary `ThreadItem` type is unchanged
  in both export profiles. Sedes continues using
  normal thread/turn/item history and does not add a raw-event parser.
- `ReviewStartParams` documents deprecation of detached review delivery.
  Sedes does not adopt `review/start`; no route migration is required.

These deltas establish no required production parser change for Sedes' adopted
surface. The parser, development fixture, and minimum supported release remain
0.153.0. The release qualification adds no provider or normalized UI feature.
Other compiled backends retain their current behavior and compatibility policy.

## Execution evidence and limits

The separate Linux qualification result records actual production-codec
execution with an isolated Codex home and loopback deterministic Responses
fixture. Schema review alone is not evidence that a method or interaction ran;
consult the result's explicit methods, notifications, and interaction outcomes.

Artifact verification and offline qualification do not establish live-provider,
authenticated-account, macOS, Windows, real SSH, external WS/WSS, or interactive
managed-TUI correctness. CLI help acceptance and fake-transport regression tests
are bounded evidence for launch arguments and orchestration. Relevant gated
live suites remain additional verification, subject to explicit authorization.
